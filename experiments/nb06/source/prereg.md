# NB06 取得前カード

2026-10-08 / v0.1。設計と実装までユーザー承認済み、GPU未測定。

問い：NB05と同じ4文章・128-token prefillで、継続256 stepと追加圧縮を行うと品質と累積費用はどう変わるか。

H1：公式一致・全slotの保存/経路・過去blockの不変性・32点の実Q数値予算・同方式反復一致が全4文章で成立。
H2：融合対NATIVEの全256予測と終盤64予測が全4文章でPPL悪化5%以内。改善や統計的非劣性は要求しない。
H3：主256-step decode（forward＋post_decode）CUDA時間の融合/全量復元対応比を各文章3反復中央値→4文章中央値で集約し1未満。
償却点の方向は予想しない。8/64/128/256の固定点すべての初期費用込み比を報告し、外挿・成功するまでの延長なし。

4冊は9667/26438/45277/28881。本文hashと先頭137 tokenをNB05に照合し、同tokenizerで385 tokenをモデルロード前に固定。60系列×257＝15,420 forward、3方式3技術反復。旧データとプールしない。technical replicatesも窓も独立の文章数へ加えない。追加圧縮4回のうち後続利用は3回を観測。

全位置でNLL成分とlogit hashを保存、固定8位置×48系列は全語彙logitsも保存。非保存位置のraw再検算はできない。詳細数値はstep1/65/193/256×slot0/43。固定予算はNB05から継承する。

有限の予算超過・品質悪化・速度低下は予定を継続。公式gate、非有限、構造/証拠/資源異常はINCONCLUSIVE、反復不安定もINCONCLUSIVE。完了・中断を問わずZIPへ原値と欠測を残す。手元GPUなし。全体105分、証拠768MiB、ZIP512MiBまで。結果は校了稿と別に記録する。
